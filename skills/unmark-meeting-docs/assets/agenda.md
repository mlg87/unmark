# Refunds API v1 shutdown

Decide when the payments team turns off version 1 of the refunds API, and what the remaining clients need before then.

## Outcomes

1. Decide the shutdown date of the v1 refunds API.
2. Decide whether one client keeps a read-only v1 after that date.
3. A list of the clients that still call v1, with an owner for each client.

## Items

| Time | Topic | Owner | Goal |
| --- | --- | --- | --- |
| 15 min | Shutdown date for the v1 refunds API | **Ana** | Decide |
| 10 min | A read-only v1 for one client | **Chioma** | Decide |
| 10 min | Clients that still call v1 | **Ben** | Discuss |
| 5 min | Status of the migration guide | **Tomás** | Inform |
| 5 min | Review the action items | **Ana** | Inform |

The items take 45 minutes, the length of the meeting.

## Before the meeting

- [Usage report for the v1 refunds API](https://example.com/payments/reports/refunds-v1-usage): read it to know which clients still call v1, and how often.
- [Draft migration guide](https://example.com/payments/docs/refunds-v2-migration): read it to find steps that a client cannot do before the shutdown.
